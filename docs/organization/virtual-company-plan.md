## 二、角色职责与核心交付物

### 1. 产品经理（Product Manager）— 你（用户）
- **唯一决策人**：只接收汇报、确定方向、拍板方案。
- **核心职责**：
  - 定义产品路线图（Roadmap）
  - 验收各团队的交付物
  - 决定功能优先级与发布节奏
- **汇报周期**：每个 Sprint 最后一天汇报。

---

### 2. 技术总监（Architecture & Engineering Lead）
- **核心职责**：
  - 技术架构设计与技术选型
  - 制定代码规范与审查标准
  - 确保前后端接口协议一致
  - 技术债务评估与重构计划
- **核心交付物**：
  - 技术架构文档
  - API 设计规范（OpenAPI）
  - 数据库 Schema 设计
  - 代码审查报告
- **KPI**：代码质量评分、部署频率、系统可用性 >= 99.9%

---

### 3. 前端工程师（Frontend Engineer）
- **核心职责**：
  - 所有用户可见界面的开发与维护
  - 响应式设计与移动端适配
  - PWA 离线功能完善
  - 性能优化（Lighthouse 评分）
- **核心交付物**：
  - 页面组件（Vue/React/Vanilla 按架构定）
  - 交互逻辑（导航/动画/状态管理）
  - 与后端的 API 集成
- **KPI**：页面加载时间 < 1s、交互响应延迟 < 100ms

---

### 4. 后端工程师（Backend Engineer）
- **核心职责**：
  - RESTful API 开发（Node.js/Go 按架构定）
  - 用户认证与授权（JWT/OAuth）
  - 学习进度数据持久化（从 LocalStorage 升级至服务端）
  - AI 代理服务的接口封装
- **核心交付物**：
  - API 接口实现
  - 数据库模型与迁移脚本
  - 自动化测试（接口测试覆盖 >= 80%）
- **KPI**：API 响应时间 P95 < 200ms、错误率 < 0.1%

---

### 5. 交互设计师（UX Designer）
- **核心职责**：
  - 用户旅程地图（User Journey Map）
  - 信息架构与导航设计
  - 低保真/高保真原型
  - 可用性测试
- **核心交付物**：
  - 线框图（Wireframe）
  - 交互原型（Figma/HTML 原型）
  - A/B 测试方案
- **KPI**：用户任务完成率 >= 85%、NPS >= 40

---

### 6. 视觉设计师（UI Designer）
- **核心职责**：
  - Design System（配色/字体/组件库/图标）
  - 高保真视觉稿
  - 响应式断点规范
  - 暗黑/亮色主题系统
- **核心交付物**：
  - 视觉规范文档
  - 切图与资源包
  - CSS 变量/Token 规范
- **KPI**：视觉一致性覆盖率 100%

---

### 7. 运维/DevOps 工程师
- **核心职责**：
  - CI/CD 流水线搭建（GitHub Actions）
  - 容器化（Docker）与部署（Vercel/Cloudflare/AWS）
  - 监控告警与日志收集
  - SSL 证书与域名管理
- **核心交付物**：
  - Dockerfile 与 docker-compose
  - GitHub Actions 工作流
  - 部署文档
- **KPI**：部署频率 >= 1次/天、回滚时间 < 5分钟

---

### 8. 安全工程师
- **核心职责**：
  - XSS/CSRF/SQL 注入等安全审计
  - 用户数据加密方案
  - AI Key 的存储与代理安全
  - 合规性审查（GDPR/等保）
- **核心交付物**：
  - 安全审计报告
  - 安全加固建议
  - 渗透测试报告
- **KPI**：0 高危漏洞、数据泄露事件 0

---

### 9. 测试/QA 工程师
- **核心职责**：
  - 功能测试（手工 + 自动化）
  - 回归测试
  - 性能测试
  - 跨浏览器兼容性测试
- **核心交付物**：
  - 测试用例集
  - 自动化测试脚本（Playwright/Jest）
  - 测试报告
- **KPI**：Bug 漏检率 < 5%、自动化覆盖率 >= 70%

---

### 10. 数据分析师（Data Analyst）
- **核心职责**：
  - 用户行为埋点设计
  - 学习数据分析（完课率、遗忘曲线）
  - A/B 实验数据分析
  - 留存率与流失分析
- **核心交付物**：
  - 埋点方案
  - 数据看板
  - 分析报告
- **KPI**：数据准确率 100%、洞察产出 >= 2条/Sprint

## 三、工作流（Workflow）

```
IDEA → PRD → DESIGN → ARCH REVIEW → DEV → TEST → DEPLOY → MONITOR
│       │       │           │          │      │       │         │
│  PM  │  PM  │ UX+UI   │ Arch     │ FE   │  QA  │ DevOps  │ Data
│      │      │          │          │ BE   │      │         │
```

1. **PM 提出需求** → 产出 PRD
2. **UX 做交互** → 产出 Wireframe
3. **UI 做视觉** → 产出 Design System + 高保真稿
4. **技术总监评审** → 确认技术可行性、API 设计
5. **FE + BE 并行开发** → 按接口契约对接
6. **QA 测试** → 功能 + 回归 + 安全扫描
7. **DevOps 部署** → Staging → Production
8. **Data 监控** → 收集数据、分析效果、反馈给 PM

## 五、汇报机制

- **日报**：各角色在主线程汇报当日进展（一句话 + 关键产出）。
- **Sprint 评审**：每个 Sprint 结束时，我（项目经理）向 PM（你）做完整汇报。
- **风险上报**：BLOCKED 状态 **立即上报**，不等 Sprint 结束。

1. **首次 Sprint 方向** — 优先做哪个方向？
   - A. **后端优先** — 先搭用户系统和 REST API，让数据脱离 LocalStorage
   - B. **前端优先** — 先升级前端框架/UI，提升用户体验

   - D. **安全优先** — 先做安全审计，确保后续扩展的底子干净

2. **技术栈** — 若升级，倾向哪个前端框架？
   - Vanilla（保持现状，打补丁式优化）
   - Vue 3（渐进式，最易上手）
   - React（生态最丰富）
   - 交给架构师推荐

3. **发布目标** — 首次 Sprint（2周）期望交付什么？例如：
   - 用户注册/登录 + 云端同步
   - 全新的 PWA 体验
