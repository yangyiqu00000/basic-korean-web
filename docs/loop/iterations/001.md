# Iteration 001 — A1：抽屉打开时冻结背景滚动

- 日期/耗时：2026-09-06 / ~25min
- 队列来源：A#1（LOOP_PLAN §5 主线 A）

## Step1 问题与反问

【问题 1】移动端抽屉打开后，背景页面仍可滚动 —— 用户在抽屉上滑动手势（或 iOS 橡皮筋）会滚动背后的页面，焦点与视觉上下文丢失，违反 iOS/Material 抽屉惯例。
- 现象/证据：`js/app.js` 的 `toggleMobileMenu()` / `closeMobileDrawer()` 只操作 nav/backdrop/aria，未触碰 body 滚动；`css/style.css` 移动媒体块只有 `html, body { overflow-x: clip }`（横向），无纵向锁。
- 反问 1（真实性）：真实。代码层面无任何滚动锁；行为层面自检扫描可复现。
- 反问 2（性价比）：高收益（标准抽屉交互契约）低风险（四条关闭途径已收敛到 `closeMobileDrawer`，两处函数加锁即全覆盖）。命中硬禁区：R6 版本戳。
- 反问 3（最小路径）：`overflow: hidden` 一行 CSS + JS 挂类 —— **第一版即此**，但被自检证伪（见【问题 2】）。
- 分论点：a) 遮罩是 `position:fixed` 但不是滚动屏障，触摸滚动穿透到 body；b) `navigate()`/ESC/遮罩/汉堡四条关闭路径全部经过 `closeMobileDrawer`（`js/app.js:1407`），锁的释放只需一处。

【问题 2】（修复过程中的二次发现，已并入本轮）`overflow: hidden` 与 `overflow: clip` 均无法锁住视口滚动：
- 现象/证据：自检新增断言实测 —— html 挂 `overflow:hidden` 后 `window.scrollTo(0,300)` 仍滚到 **149px**（hidden 盒是可编程滚动容器）；改 `clip` 后仍滚 —— **根元素的 clip 传播到视口时会按规范降级为 hidden**（CSS Overflow 3）。这正是本仓库 `overflow-x: clip` 注释里那个坑的纵向变体。
- 分论点：唯一 CSS-only 正解是让 **scrollable overflow 归零**（高度收敛一屏），scrollTo 无处可滚；代价是滚动位置被钳到 0，必须由 JS 保存/恢复。

## Step2 方案步骤

1. CSS：`html.drawer-lock, body.drawer-lock { overflow: hidden; height: 100%; }`（移动媒体块内）；
2. JS：新增 `DrawerLock` 状态 + `setDrawerScrollLock(locked)`，锁定时记录 `scrollY`，解锁时 `scrollTo` 还原；`toggleMobileMenu`/`closeMobileDrawer` 接入；
3. 自检：抽屉段加行为断言 —— 开：`scrollTo(0,300)` 后 `scrollY < 1`；关：`scrollTo` 恢复滚动且位置还原；
4. R6：版本戳 `20260830c → d`（index.html 16 处 + sw.js CACHE_NAME）。
