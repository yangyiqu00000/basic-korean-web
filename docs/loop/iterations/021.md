## Step1 问题与反问

【问题 1】STATE 候选：临境聊天输入框在移动端被虚拟键盘遮挡。
- 反问 1（取证）→ 375×667 headless 实测：输入框 sticky 视口底 609/667，布局本身成立；但 grep 证实**零键盘适配**：无 `interactive-widget` meta、5 处聊天高度全用 `100vh`（iOS Safari 键盘弹起 100vh 不收缩 → 真机上输入框必被推出可视区）。缺陷真实，只是 headless 弹不了键盘不可直接复现。
- 反问 2 → 修复路径是行业标准三件套：`interactive-widget=resizes-content` + `dvh` 回退链。零新依赖。
- 反问 3（分论点）：a) dvh 支持探测 CSS.supports 实测通过；b) 断言设计必须显式输出——静默跳过（noChat 无输出）是反模式，正是它让首次自检跑没暴露进不了聊天。

【问题 2】（写断言时牵出）自检里 `navigate('scene')` 后 **#mainContent 仍渲染拾遗页**，Vue 状态全对（vuePage=scene / vueView=scene-page / key=scene-0）。
- 反问 1（定位）→ 二分复刻 ×4 不复现（时序敏感）→ 真自检注入 Vue 侧诊断拿到铁证 → 根因：`rerenderWordList()` 兜底 `main = root || #mainContent; main.innerHTML = …`。当 `.wordlist-page-vue` 组件**尚未挂载**（快速 navigate/进出复习模式瞬间）root 为 null，innerHTML 写入把 `#vue-root`（Vue 挂载点）一并抹掉——Vue 反应式状态存活但 DOM 渲染永久失效。
- 反问 2（为什么历史 25 PASS E2E 没拦住）→ 需要特定时序窗（自检的 300ms 间隔连续切换才稳定踩中）；audit:strict 拦「同文件未防护写 #mainContent」但 rerenderWordList 是历史豁免路径（注释本意是防，兜底却成了洞）。
- 反问 3（修复最小路径）→ root 缺失时改走 `refreshCurrentPage()`（Vue 分支 pageTick++ 重建，传统分支 navigate）——两模式都正确，不再有任何裸写 #mainContent 的可能。
